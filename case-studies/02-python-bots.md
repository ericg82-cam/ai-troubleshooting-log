# Case Study 02 — Building working Python bots with no CS background

**Goal:** Build functional Python automation from scratch — despite having no formal programming education.

---

## The problem

Automation ideas are easy. Getting them to actually *run* — dependencies, environment setup, API auth, the errors that stop a script three lines in — is where most people quit. I didn't want a tutorial I could copy; I wanted working tools I understood well enough to fix when they broke.

## How I approached it

I used AI as a pair programmer, but drove it like an engineer, not a vending machine:

- **Small, testable steps.** Get one piece working and verified before adding the next, so when something breaks I know exactly what changed.
- **Read the traceback.** Every error is a location and a reason. I learned to treat the last line as the headline and work up from there instead of pasting and praying.
- **Understand, don't just paste.** When the AI handed me code, I asked *why* — so the next bug was mine to solve, not something I had to start over on.

## The result

Working automation bots that do real work reliably. More importantly: a repeatable process for going from "idea" to "running tool," and the judgment to debug it when the environment shifts underneath it.

## Why it matters

This is the core of what I do — turning a vague goal into a working technical thing, fast, using AI as leverage instead of a crutch. The language or framework is interchangeable. The process isn't.

## Transferable skill

Python scripting · API integration · dependency/environment troubleshooting · reading tracebacks · AI-assisted development with real understanding.
